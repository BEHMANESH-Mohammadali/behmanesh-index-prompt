# DHR-0007 — BSI v3.5 Unified Generator Architecture

**Status:** Accepted architectural direction  
**Scope:** BSI Master Prompt / analysis architecture  
**Branch:** develop/v3.5

## Decision

BSI v3.5 is to operate as a single analytical generator rather than as a collection of independent analytical and procedural reports.

The architecture is separated into four layers:

1. Layer A — BSI Intellectual Core
2. Layer B — Execution Architecture
3. Layer C — Analytical Output Contract
4. Layer D — Audit / Machine Trace

## Core Preservation

The BSI intellectual core remains invariant.

This decision does not redefine or reweight D1–D7, alter their definitions, change the BSI analytical ontology, or silently change scoring semantics.

D2 is not redefined by this architectural decision.

## Execution-to-Output Firewall

Execution, verification, evidence-control, EIG, ECC, and REIG mechanisms primarily operate as internal reasoning and quality-control mechanisms.

Their substantive effects must enter the analytical result.

Their procedural execution, intermediate states, control steps, and workflow must not normally become analytical content.

Material failures and limitations remain reportable when necessary to correctly represent the reliability of the result.

## Effort Conversion

Additional reasoning effort must produce additional analytical value through greater coverage, depth, verification, synthesis, inferential reliability, or uncertainty calibration rather than procedural narration, redundant explanation, or output length.

## Audit Semantics

Audit information distinguishes:

- Claimed
- Observed
- Independently Validated

A model's self-report is not independent evidence of execution.

## Output Contract

The user-facing result is one coherent analytical object.

D1–D7 remain official analytical criteria. Treating them as analytical lenses does not authorize omission of their required substantive output.

## Null Findings

Meaningful absence, including meaningful negative or null findings, may be substantive analytical results and must remain representable.

## REIG

REIG remains an analytical correction mechanism.

Where correction is required, the intended architecture is:

REIG → correction → re-analysis → final validation.

## Canonicalization Requirement

No unresolved conflict involving EIG, ECC, REIG, scoring, longitudinal handling, penalty logic, or implementation semantics may be silently resolved in code.

A Canonical Specification Matrix must precede such implementation changes.

## Layer C Change Rule

Layer C is not the BSI intellectual core, but changes to the analytical output contract must be explicitly versioned and documented.

## Non-Scope

This decision does not define any benchmark, comparison, ranking, winner selection, external judge, or competitive evaluation mechanism.

Those concepts are outside the scope of the BSI analysis repository.
